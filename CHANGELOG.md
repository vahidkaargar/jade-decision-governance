### Fixed
- Installation and health (review cluster E: F37-F40, G05):
  - **Newly failing:** `jade check` (and so `jade maintain`) exits non-zero on dead wiring it used to pass: a hook command whose binary is missing or not executable, `disableAllHooks`, an event or matcher that is not the one `hooks install` writes, a registered command that does not decide on a synthetic event (the PreToolUse command must block a `jade permit approve` call with SI-09; probed in a throwaway `JADE_HOME`, gate forced to enforce), gate mode `off`, a `JADE_GATE_MODE` that disagrees with the configured mode, `permissions.defaultMode` bypassPermissions or auto with an advisory or off gate, and a `jade maintain` LaunchAgent that launchd has not loaded. Hooks are recognised structurally (program named `jade`, command ending `hook <name>`), so `echo jade hook pretool` no longer counts as installed. Advisory mode still passes.
  - The launchd plist sets `PATH` and `HOME` (values escaped), and the `jev shim` row also looks beside `jade`, so the daily job no longer fails its own check under launchd's minimal PATH. Re-run `jade launchd-plist` and reload the job to get the new plist.
  - `hooks install`, `hooks uninstall`, `gate <mode>` and `claude-md apply` write atomically (temp file in the same directory, then rename), follow a symlink to its target, keep the file's permission bits (new settings files are 0600) and never overwrite a backup (`.bak-jade-<time>`, then `-1`, `-2`). `uninstall` removes only JADE's own hooks, does nothing for a missing file and refuses invalid JSON without writing. The hook command quotes the binary path.
  - `claude-md apply` ends the Jev section at the next heading of the same or a higher level, ignores headings inside code fences, and refuses a Jev heading that appears twice.
  - **Newly blocked (SI-11):** an agent command that sets `JADE_GATE_MODE`, `JADE_POLICY_DIR`, `JADE_CONFIG` or `JADE_HOME`, wherever the assignment is written, read-only commands and quoted profile text included. This includes ad hoc `JADE_HOME=$(mktemp -d) jade ...` runs by an agent while the hooks are installed; run those in your own terminal. `jade check` lists all gate variables (row `gate overrides`, also from the Claude settings `env` block; `JADE_ACK_OVERRIDES=VAR,...` acknowledges a deliberate one in your own shell) and SessionStart shows and journals a weakening override that is in force (event `gate_override`). Documented, not closed: W-46, W-47.
- Judging, adapter, calibration and improvement (review cluster D: F15, F24-F34, F44, F45, F47):
  - A repeat is judged in the calibration group of the call that produced its answer (the cached row stores `resolved_model`), never in `unknown`, and is never looser than the first verdict: a promoted stricter accept is no longer undone by asking again. A response with no model string is judged at the strictest accept any calibrated group of its family holds, with a warning. Only an answered call (DONE, exit 0, 3 or 4) anchors a repeat, so an errored original no longer turns every later answer into an invisible "repeat"; rows left EVALUATING by a dead process are closed as errors after 10 minutes.
  - Answers are checked against the question that was asked. **Newly exit 5 (previously exit 0 or a wrong verdict):** a score answer to a noul question, `noul: true`, a probability outside [0, 1] or NaN, a choice that was not offered or is not the most probable option, a response that omits a requested key. A missing companion answer at risk medium or above is ABSTAIN. `judge()` raises on an unknown type instead of accepting it. A choice whose top option is the question's `no_match_option` (`none_of_these`) is **ABSTAIN, exit 3** (it was exit 0). `require_companion_presence` was dead config and is removed; the `any_fits` companion is not batched (docs/03).
  - Exit-code contract on every error path: a missing or unreadable `--state-file` or `--field name=@file`, undecodable text, a stdin that is not text and `verify` with no evidence are exit 6 (journaled); a transport or parse failure of any kind (including a truncated body, a non-dict `usage`, a non-numeric cost) is exit 5; any exception on the path finishes the open rows and exits 5. **Newly exit 6:** `jev verify CLAIM` with empty evidence (the original sent it), a `noul` with equal or blank criteria.
  - The 20 s deadline is a wall-clock limit on the whole exchange (the body is read against it and a timer shuts the socket), no attempt starts after it, the 1 s floor is gone and a late answer is not accepted.
  - `JEV_MODEL` is the default model again (`--model`, then `JEV_MODEL`, then `config.json`); the payload of `noul`, `choice` and `score` is tested against `tests/fixtures/legacy_jev.py`; the intentional `verify` divergence is documented (ADR-03).
  - Calibration counts distinct `(claim, state)` pairs: cached repeats and answers with no model string are no longer labels (210 asks of one claim made a group eligible and proposed accept 0.50). The outcome join labels only the call that gated the decision (the last `evaluation_refs` entry, accepted), not companions or other claims; a validation-split check is part of the replay.
  - `jade fast` writes an event (`FAST_CHECK`), not a `jev_calls` row: no more dedup, repeat shares, `repeat_without_new_evidence` patterns or Stop-hook reminders from deterministic checks. Rows an older version wrote are ignored by stats, the miner and the Stop hook.
  - Promotion consumes what the system computed. `promote` recomputes every result from evidence only the evaluators write and reads `policies/promotion.yaml` for each limit; `attach_results` refuses result and evidence keys. A candidate must be undecided (a promoted or rolled-back one is not promoted again). New: `jade improve protected` (human terminal) and `jade improve canary`; `ops.set_challenger` is capped at the policy's canary fraction (**a larger fraction is now an error**); a question template needs shadow (7 days, 100 samples, no reject-to-accept flip), the protected check and a canary of the shadowed version. **Newly blocked:** promotion of any target without an evaluator (`cache_ttl`, `routing_heuristic`, ...), which could not pass before either (nothing computed the required results). Tracked as W-44.
  - `jade improve rollback` restores the exact prior champion pin (the registry default when there was none) or the prior threshold band, and refuses when the pins no longer match the promotion. Under `FREEZE` it needs a human terminal; loosening a promoted stricter threshold needs one too. The audit trail records the real actor (`runtime:agent` outside a human terminal; a caller-supplied `human:terminal` is ignored). `ops.rollback` restores `previous_champion` when no challenger is set.
- Judging and improvement, second pass (review cluster D, verifier findings):
  - `jade improve rollback` touches only what its own candidate put live. Rolling back a shadow or pending question template used to clear a canary or restore `previous_champion` of the question (`None == None` matched), silently undoing an earlier promotion; it now clears a challenger only when this candidate's own canary is the one serving. Rolling back a promotion while a later challenger serves the question is **newly refused** (it reported "champion restored" while only clearing that challenger and left the champion in place); retire the challenger first. The restore is checked, not assumed.
  - **Newly blocked:** an agent reverting a promotion a human made (the promoted audit entry names a human actor). A promotion the runtime made under the human's standing opt-in can still be reverted by an agent, so a drift rollback still works; docs/05 T11.
  - The provider transport honours `HTTPS_PROXY`/`HTTP_PROXY` and `NO_PROXY` again (the move from urllib to `http.client` dropped them): https through a CONNECT tunnel, plain http as an absolute-URI request, `user:pass@` proxy credentials, `NO_PROXY` bypass. Only an `http://` proxy URL is spoken; any other scheme is a transport failure (exit 5), never a silent direct connection.
- Redaction and egress (review cluster C: F14, F17-F23):
  - Nothing credential-shaped is stored in the ledger any more. The ledger redacts `state_text`, `question_text` (so also `jade fast` arguments), event `guard` and `detail` at its own choke points; decisions (objective, command, candidate actions, constraints, assumptions, evidence references) and outcomes are redacted before they are written (`decide.scrub`); the permit's review context stores the redacted command. The plan hash still covers the raw command. Email addresses are kept in these local records.
  - **Newly unapprovable:** a gated command that carries a secret-shaped value on its command line (`--token=...`, `DB_PASSWORD=... cmd`, `curl -u user:pw`) raises a PENDING permit that `jade permit approve` and `jade permit show` refuse (a human cannot check from a redacted text what the hash covers); the block message tells the agent to pass the secret in an environment variable or a file. Tracked as W-43.
  - `jade ledger purge` also clears decision objective, command and evidence text, the command of a permit that is no longer open, and event detail, after the retention window; metrics stay (docs/05 T15).
  - The database and its `-wal` and `-shm` files are created mode 600 before SQLite opens them (not after, so no umask leaves a readable sidecar); an existing file and its sidecars are tightened on open.
  - `redact()`: PyPI, `xapp-`, Slack and Discord webhook URLs, `ya29.`, `GOCSPX-`, Stripe `whsec_` and `pk_`, Twilio `SK`, SendGrid; Azure `AccountKey=` and SAS `sig=`, `X-Amz-Signature`; `pass`, `pwd`, `api-key`, `x-api-key`, `auth key`, `account key`, `cookie` key names; `Cookie` and `Set-Cookie` values; `curl -u`, `mysql -p`, `--password PW`; escaped JSON, `[value]` forms and annotated assignments; URL userinfo with an empty user name or an `@` in the password; the line printed under `security find-generic-password -w` (the documented Keychain claim was not implemented; now it is); PGP private key blocks. `residual()` is now the union of the high-confidence patterns instead of a short separate list.
  - Over-redaction removed: `max_tokens=4096`, `token_count`, `TOKENIZERS_PARALLELISM`, `secret_name`, `api_key: str`, `token: Optional[str] = None`, `$TOKEN` and `${VAR}`, `PASS:` and `PWD=/path`, `git@github.com:org/repo.git` and `ssh://git@host/...`, `authorization: required`, and a URL port (`host:8080/x@...`) are no longer redacted. Numeric passwords still are. **Newly redacted (previously passed):** every shape listed above, and a `Cookie` header.
  - `jade ask --dry-run` runs the same preparation as a real call (`ask.prepare`) and prints the redacted state, with the redaction count on stderr; an invalid-question error no longer quotes the raw `--field` value and is redacted before it is printed and journaled.
  - Documented, not closed: shape-less secrets (W-42), docs/05 section 3 rewritten, including the corrected Keychain claim.
- Redaction, second pass (review cluster C, verifier findings):
  - `redact()` is linear in the length of the text. `password=[` with no `]` made the `[value]` branch scan to the end of the text from every start (150 KB took 13 s through the PreToolUse hook, past its 10 s timeout, so the host killed the hook and a critical command ran). A `[value]` is now read up to 256 characters and a longer or unclosed one up to the next blank; the annotated-assignment bracket is bounded; the `curl -u` and `mysql -p` patterns (also quadratic) find the flag first and look back for the command word within one command and 2000 characters. `test_redaction_is_linear_on_adversarial_text` runs 33 unterminated shapes at 150 KB.
  - A reference is not a secret: `$VAR`, `${VAR}`, `"$VAR"` and a fetch (`$(cat f)`, `$(op read ...)`, `$(pass show x)`, `$(security ... -w)`, and the other secret stores) are left alone after `--token`, `--password`, `curl -u user:`, `mysql -p` and in assignments, so the remedy the block message gives (use an environment variable) leaves the command approvable. `$(echo S3cret)`, a heredoc or a literal beside a reference (`pre$X`) stays redacted, now as a whole substitution (`--token=$(echo S3cret)` used to leave `S3cret)`). Keys ending in `_type`, `_url`, `_uri`, `_ref`, `_file`, `_path`, `_dir`, `_ttl`, `_expires`, `_expires_in`, `_endpoint`, `_header`, `_prefix`, `_alg`, `_kind` or `_scope` (also camelCase) are settings, not credentials (`TOKEN_TYPE=bearer`, `token_url=...`, `secret_ref: x`). **No longer redacted (previously harmless commands that were unapprovable):** those forms.
  - **Newly redacted:** `curl -uUSER:PW` and `--user=USER:PW`, `docker`/`podman login -p`, `sshpass -p`, `redis-cli -a` and `--pass`, `htpasswd -b`, `mongosh -p PW`, `unzip -P`, `sqlcmd -P`, `ldapsearch -w`, `openssl ... -passin pass:`, `--http-password`, `--passphrase`; `?key=` and `&key=` query values; `api key: ...` with a space; Slack `xoxc-`/`xoxd-` and other `xox?-` tokens (URL-safe characters), scheme-less and `http://` Slack and Discord webhook URLs, `hooks.slack.com/workflows/` and `/triggers/`; the Keychain output line after `security find-generic-password` with `2>/dev/null`, combined flags (`-wa`, `-ws`, `-gw`) or an absolute path to `security`. A short flag counts only behind its own command (`ssh -p 2222` is a port). A `$(...)` or pipe still redacts nothing after a Keychain read: there is no output line to hide.
  - `jade ledger purge` now reaches the file. The ledger opens with `secure_delete=ON` and a purge that cleared rows runs `VACUUM` and a `TRUNCATE` checkpoint (`Ledger.scrub`), so cleared text is no longer readable in free pages or in the write-ahead log (a byte scan of `jade.sqlite` and `-wal` found it before). The file system may still hold freed blocks of the old file; that is outside JADE.
- Permits, second pass (review cluster B, verifier findings on F06 and F07 and six new defects):
  - Permit rows are sealed. A permit that becomes ISSUED (`permits.issue`, `permits.approve`) carries an HMAC over its plan hash, risk, principal, approval reference, scope, decision, expiry, policy version and preconditions, made with `permit-seal.key` (32 random bytes, mode 600, next to the ledger, created only when a permit is issued or approved). The hook ignores a permit whose seal does not match or whose key is missing, so a row rewritten with SQL (a low permit edited into a human's critical approval), a swapped plan hash or an extended expiry is refused; a `permit_consumed` event also stops a consumed permit set back to ISSUED. The key is readable by the same OS user, so this stops a row edit and not a process that reads the key: docs/05 T19 and T20, work item W-41. New invariant SI-10 blocks a command that names the key file. **Behaviour change:** permits that were ISSUED before this upgrade have no seal and must be approved again.
  - `jade permit approve -y` is refused at every level (it never skipped the typed code; the help text now says so). `human_approval_required_at` in `policies/risk.yaml` is now read (`policy.human_floor`, never above `high`); the code used to read only `permit_required_at`.
  - The ancestor check matches the program and the script an interpreter runs, not every word of an ancestor's command line, so a human shell started under a path such as `~/claude-code/` is no longer refused; the native binary under `.../claude/versions/` is now recognised. The double-fork variant (setsid, `pty.fork()`, stripped environment, reparented to launchd) still approves: documented in T2, W-38.
  - SI-09 no longer blocks `pytest /path/jade/tests -k approve` (the word `jade` must stand alone, followed by a space or an expansion), `docker exec jade-svc approve`, or `ln -s /opt/x/jade /usr/local/bin/jade2` (only the installed launcher, `uv/tools/jade` and `which jade` are wrapped). It now also blocks a variable set to `approve` (`ap=approve; jade permit $ap`). Using `jade.cli`, `jade.permits` and the other human-only modules from Python stays blocked even when read-only (`python -m jade.cli ledger stats`): the classifier splits a command at every `;`, so the import cannot be tied to the call that approves; use `jade ledger stats`. **Newly blocked:** any command line that names `permit-seal.key` (SI-10).
  - `find_usable` takes the session and agent: the newest permit of the calling session is used, a newer permit of another session no longer shadows an older one. A pending permit of another session is no longer revoked when a second session asks for the same command (two agents retrying used to invalidate every id the human was shown); a pending permit is still superseded when the policy or a recorded precondition changed.
  - `plan_hash` trims only space, tab and newline from the ends of a command. A no-break space, an ideographic space, `\r`, `\x0b` or `\x1f` at the end is part of the last shell word, so a permit for `rm -rf /x/y` no longer covers `rm -rf /x/y\u00a0`. **Newly blocked:** a retry that differs from the approved command by such a character.
  - A NUL byte in a command no longer raises in the classifier: the text is read as the shell reads it (NUL dropped) and the plan hash covers the text as written.

- Permits and the decision lifecycle (review cluster B: F06-F13, F16, G08). The hook no longer trusts what a permit row says about itself, and a decision can no longer be walked to a result nobody observed:
  - At use, in one transaction (`permits.try_consume`): the permit's risk level is not below the risk of a fresh classification (a critical command needs a critical permit), a high or critical command needs a human principal and a `tty:` approval reference on the permit (a row made with `permits.issue(risk="low")` or by hand no longer opens the gate), `policy_version` is unchanged (a change revokes every open permit), every recorded precondition still holds (for `git push`, the HEAD commit of the repository it runs in), the permit was requested by the same `session_id` and `agent_id`, and the decision it belongs to is live. `permits.consume` and `find_usable` take the assessed `level` as a required keyword.
  - `plan_hash` hashes the command exactly as written (only its ends are trimmed, so `rm -rf "my  dir"`, a heredoc with other indentation and a newline instead of a space are different plans) and the symlink-resolved cwd. Permits approved before this upgrade no longer match and must be requested again.
  - The approval screen shows the whole command with control, bidirectional and zero-width characters escaped, its length and the first 12 characters of the plan hash, the request age and the rule. Approval refuses a command longer than 20000 characters, a scope that was cut or does not hash to the permit, an expired request (it used to revive an expired PENDING permit with a fresh TTL), and a decision that is cancelled, expired or finished. `jade permit approve` no longer accepts `-y` for a high or critical permit (every permit `jade permit request` makes): type the 6-character code shown.
  - A cancelled, expired or finished decision revokes its open permits in the same transaction; the permit consume and the decision steps (`human_accept`, `authorize`, `execute`) are one transaction (a crash between them leaves the permit unused); the gate sweeps expired decisions before it looks at a permit.
  - `jade decide event` sends only what an agent may send (`state_machine.agent_may`): evaluation results, evidence, escalation, `authorize`, `cancel`, and `execute` below risk high. `observe`, `verified`, `failed`, `unknown`, `reconcile`, `deadline`, `context_changed` and the `human_*` events are not available to it; `verified` is refused (also in process) unless the latest outcome row is observed with success true, so the six-event walk to SUCCEEDED ends at EXECUTING. A session other than the owner may only cancel; cancelling a decision that is EXECUTING, VERIFYING or OUTCOME_UNKNOWN needs a human terminal because it lifts the SI-07 hold; `deadline` is refused before `expires_at`.
  - Every non-terminal state has an exit: `NEEDS_REVISION --escalate--> WAITING_HUMAN`; `deadline` now ends every waiting state (it used to cover three), the sweep turns an EXECUTING or VERIFYING decision with no outcome into OUTCOME_UNKNOWN and leaves an unknown outcome alone; `record_outcome` and the sweep run in one transaction. `Ledger.tx()` is re-entrant (savepoints).
  - SI-09 matches words, not one spelling: `env`, path-qualified, `uv run`, `python -m jade`, `script`, `xargs`, quoted or expansion-split (`jade ${X:-permit} approve`), the bare pair `permit approve`, `$VAR hooks install`, an alias, function or symlink that wraps jade, and `jade.state_machine`. **Newly blocked, previously allowed:** an unquoted command containing the words `permit approve`; `alias x=...jade...`, `f() { ...jade...; }`, `xargs ... jade` and `ln ... jade`; `from jade import state_machine`.
  - Human-terminal check (`util.human_tty_refusal`): besides tty and environment (`AI_AGENT` added) it walks the process table and refuses when an ancestor is an agent (`claude`, `codex`, `cursor-agent`, an `@anthropic-ai/claude-code` entry point); it refuses when the table cannot be read. A pty with a cleared environment no longer approves. A human who starts `claude` and approves from inside it is refused too. Still a heuristic: a detached process escapes it (docs/05 T2, W-38).
  - Documented, not closed: W-38 (out-of-band approval), W-39 (Write/Edit content is not bound to the permit), W-40 (live payload fixtures, PostToolUse for Write/MCP, parallel-hook permit burn). docs/05 T2, T6, T8, T19 corrected and T20 added.

- Gate bypasses found by the adversarial review (cluster A1: F00-F05, F35). One canonicalisation step, `jade/shellnorm.py`, now runs before every risk rule, safety invariant and the push resolver:
  - git global options (`-C`, `-c`, `--git-dir`, `--work-tree`, `--no-pager`, `-P`, `--exec-path`, `--namespace` ...) no longer hide `git push`, `reset --hard`, `clean`, `branch -D` or SI-08; `git -c` keys that run programs (alias, core.sshCommand/pager/editor/fsmonitor/hooksPath, credential, url ...) and `--exec-path` are the new high rule R-15.
  - Backslash escapes, line continuations, `$'...'` strings and adjacent quotes are resolved before matching; a `<<` inside quotes can no longer swallow the lines after it.
  - Command substitutions inside double quotes, backtick spans and unquoted heredoc bodies are classified; a heredoc, here-string, pipe or process substitution that feeds `sh`/`bash`/`zsh`/interpreters, and the program text of `python -c`, `perl -e`, `node -e`, `awk` and `sed 'w ...'`, are searched for literal commands.
  - The `read_only` list can no longer write: `sort -o`, `uniq IN OUT`, `sed` `w`/`e`/`-i`/`--in-place`, `awk`/`gawk` programs with `system`, redirects or `-i`, `git diff|log|show --output`, `find -fprint/-fls/-okdir`, `xxd -r` or two operands, `yq -i`, `tree -o`, `less -o`, `date -s`, `fd -x`.
  - SI-08 parses `git push` arguments: refspec destinations, `refs/heads/` and `heads/` forms, `-o`/`--push-option`/`--repo` values, `--force-with-lease=...`, `HEAD`/`@`/empty refspec resolved against the real current branch (relative `-C` resolved against the event cwd), `--all` and `--mirror`; the remote's default branch name (`origin/HEAD`) counts too.
  - Write, Edit, MultiEdit and NotebookEdit paths are expanded (`~`), resolved against the event cwd, symlink-resolved and matched case-insensitively (R-01 path, R-04 key files and R-13 are case-insensitive, as the macOS filesystem is); Bash path tokens are folded (`//`, `/./`, `x/../`).

- Gate bypasses found by the second adversarial pass over cluster A1 (F01-F03 variants and new defects N1-N7). The classifier now has one table of what each read-only verb can write or run, and the scanner resolves the words a shell receives:
  - Performance: the scanner is linear (stage text is kept as head and tail, plain runs are matched in bulk) and has a 4-million-character work budget across nested levels; 80 KB of quoted words took 54 s and nested `sh -c` quoting 10 levels deep took 60 s, now both are under 0.2 s and anything past the budget degrades to plain text search.
  - `eval` and `sh -c`/`su -c` take the joined words of the command, so `eval "git" push origin main`, `sh -c "git"' push origin main'`, `sh -c git\ push\ origin\ main` and nested POSIX quote escapes are seen; positional parameters (`sh -c '$0 push' git`), `eval "$(echo ...)"` and `\`` nested backticks are resolved.
  - Pipelines: every earlier stage of a pipeline counts as input of a shell reader at its end (`echo ... | tee /dev/stdout | sh`), and `xargs sh -c`, `source /dev/stdin`, `. /dev/stdin`, `bash /dev/fd/0` read stdin as code; nested `echo '...| bash' | bash` is parsed level by level.
  - Comments end at the newline even after a trailing backslash (`echo hi #\` + newline + `git push origin main` ran the push); brace lists are expanded (`git push origin m{a,}in`).
  - Read-only verbs: `sort --out=`/`--o`, `uniq -f 1 IN OUT`, `xxd -c 8 IN OUT`, `sed 'w/path'`, `sed w/path`, `less --log-file`, relative operands after `cd`; exec options of `less +!`, `man -P`, `rg --pre`, `bat --pager`, `sort --compress-program`, `fd -x`, `find -exec`, `git fetch --upload-pack`, `git rebase --exec`, `git submodule foreach`, `git bisect run` and environment variables such as `LESSOPEN`, `PAGER`, `GIT_PAGER` are classified as the commands they run.
  - cwd tracking: `cd`, `pushd` and `popd` are followed for `git push` HEAD resolution (SI-08) and for relative operands, so `cd main-repo && git push origin HEAD` is blocked and `cd /etc && sort -o pf.conf in` is critical.
  - Low-severity gaps: `git clean -f -d`, `git clean --force -d`, `git branch --delete --force`, `git branch -vD`, `git reset --har`, `rm -r -f`, `rm -fr`, `rm --recursive --force` are R-11; `GIT_SSH_COMMAND`, `GIT_PAGER`, `GIT_EDITOR`, `GIT_ASKPASS`, `GIT_EXEC_PATH`, `GIT_CONFIG_*` set to something that runs a program are R-15; Write/Edit/MultiEdit/NotebookEdit with `path`, `filePath`, `file`, `filepath`, `target_file`, `file_name` or any unknown key are classified; R-12 and the production-path check are case-insensitive.

- Gate surface and failure behaviour (review cluster A2: F36, F41, G00-G04, G06):
  - PreToolUse fails closed (T17). A corrupt, locked or full ledger blocks every call at or above the permit floor (it used to exit 0 for all but `git push`/`docker compose`); a policy or overlay that does not load blocks everything except clearly read-only commands and ordinary file writes; an unresolved push destination (git timed out) blocks a high-risk call. The hand list `FALLBACK_HIGH` is gone. Every wait is bounded: ledger lock 1.5 s, git 2 s, and the whole handler runs under a 6 s alarm (host timeout 10 s) that lands in a policy-free linear fail-safe. `ledger.open(path, timeout=)` takes the timeout.
  - JADE's own runtime artifacts are protected targets (R-13): `jade.sqlite` and `-wal`/`-shm`/`-journal`, `calibration/current.json`, `~/.config/jade` (also without a trailing slash), `~/.local/share/jade`, the uv tool directory, Bash writes to the `jade`/`jev` launchers, `uv tool uninstall/upgrade/reinstall` and `uv tool install` naming jade, `policies/*.yaml` and `policies/loader.py`, and the gate code `jade/ops.py` and `jade/paths.py`; `launchctl bootout/unload/disable` is R-12. The program word of a segment is no longer resolved as a written operand, so `~/.local/bin/jade check` stays low.
  - Tool surface: the matcher is `Bash|PowerShell|Monitor|Write|Edit|MultiEdit|NotebookEdit|RemoteTrigger|mcp__.*`; re-run `jade hooks install` (`jade check` reports a narrower installed matcher). MCP tools are classified by name: governance wiring (permission mode, settings, scheduled tasks, MCP profiles, sending to another session), nested executors (`mcp-exec`, `code-mode`) and `RemoteTrigger` are high; file-write tools also get the path rules (a write to `/etc/pf.conf` is critical); text typed into a shell through `interact_with_process`, `app_type`, `computer_batch` is classified as a command; a tool whose name says it writes, deletes, executes or sends is high (M-07), a read-only name is low, anything else is medium (M-99). Subagent tool calls reach the same hook; `agent_id` is journaled.
