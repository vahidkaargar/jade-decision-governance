## [Unreleased]

### Added
- **R-18 (high): creating a skill, command or agent instruction file needs a permit (W-54, T3).** Decision by the human, 2026-11-09: a new file under `.claude/skills|commands|agents/`, `.agents/`, `.cursor/skills|commands|agents/` or `.skills-archive/` is high; editing a file that already exists stays low, because the agent maintains its own skills daily. Covers Write, Edit and MultiEdit paths and Bash that creates a file there (redirect, `tee`, `touch`, `cp`/`mv`/`ln`/`install`/`rsync` destinations, `curl -o`, `tar -x -C`, `unzip -d`, and `git clone` into the directory, the current directory or a `-C` directory). New rule key `creates_only` (`jade/policy.py` `_creates`, `creation_view`): a target that resolves to an existing regular file is an edit; a missing path, an existing directory, a glob or an unresolved variable in the file name is a creation (a variable or glob in a DIRECTORY name is a computed path, a residual). Removals (`rm`), reads, `grep`, `ls`, `git add`/`commit`, `mkdir`, and a path that only appears in a commit message or heredoc body are not matched. Review round 2: a verb outside the writer list (`npm test`, `make`, `python3 x.py`, `sed -i`, `perl -pi`) names a skills directory only by naming a path to it, so running it from inside a skill directory is not a creation; a git verb other than `clone`, `init`, `worktree` and `submodule` creates nothing (`git -C ~/.agents/x pull|checkout|stash`); `mv` of skills that already exist (retire to `.skills-archive`, rename to `.disabled`) creates nothing; a trailing redirect (`2>/tmp/err`, `> log`, `&>f`) no longer hides the destination of `cp`/`mv`/`ln`/`install`/`rsync`; `mv -vt`/`-t<dir>`, an attached `-o<dir>`/`-d<dir>`/`-C<dir>`/`-P<dir>` and `$HOME`/`$PWD` spellings count; `tar -x`, `unzip`, `curl -O`, `wget`, `7z x` and `ln -s target` write into the current directory; a directory named `name:` is no longer taken for a URL (a URL is only a word that starts with one). `CLAUDE.md` and the settings files stay R-13. **Newly gated:** every previously low creation of such a file; your own terminal is unaffected, so install skills there. - **Tests and verification runs stay out of the live ledger (W-72).** `tests/conftest.py` now fails any test that reaches the real JADE home before it is created, opened or migrated. A run that must use the live hook or ledger sets `JADE_SOURCE=test`: the new `source` column (added to `jev_calls`, `decisions`, `permits` and `events` by the automatic migration; older rows stay NULL) tags every row it writes, `jade ledger stats`, the miner, the calibration labels and the `host permission prompt` count leave tagged rows out, SessionStart reports them apart from real approvals, `jade permit list` marks them `[test]`, and `jade ledger purge --test-rows [--id prm_x|dec_x ...]` (human terminal only) removes them. The tag changes no gate decision, but a tag that is in force in the hook environment is listed by `jade check` and shown at SessionStart as a weakening override (it hides gated calls from the statistics), and a live call is never marked a repeat of a test call. Runbook: docs/08 section 1.2.
- **SI-10 gates the Read, Grep and Glob tools for the permit seal key (W-70).** A Read of `permit-seal.key` (by name, symlink or hard link), a Grep of the directory that holds it with no file filter that excludes it and a Glob pattern or Grep `glob` that would match its name are blocked as SI-10; every other read, the rest of the JADE home included, is not gated. Reports name the file and key, never the command text. SessionStart journals a `gate_override` event once per session and prints a notice. It never blocks. Run `jade check` from the project directory you want scanned.

Findings name the file and rule id, never the pattern or host.

A grep or test that mentions the seal key's file name, a note about `JADE_HOME=`, a commit message that quotes a human-only command are no longer blocked; a read, copy, glob, symlink or assignment is, as before. Anything the scanner cannot read exactly is matched whole. Measured on 103 synthetic commands: 72 blocked before, 7 after; every earlier SI-09/10/11 test and adversarial case passes unchanged. New tests `tests/acceptance/test_si_narrowing_w71.py` (35 false-positive twins, 86 effect twins), regression cases R110-R127, adversarial cases A164-A175. No human-run dev mode was added (docs/05 T19: a switch the hook reads is either an environment variable SI-11 exists to close or a file only a permit can write).

### Known limits
- A heredoc body that names the seal key or a gate variable can be written to an ordinary file by `cat > f <<'EOF'` (W-71); the Write tool already allowed this. See docs/05 T19. "Ordinary" excludes a file a shell or tool runs: a hidden file, a script by extension, anything in a `bin` directory, the Claude settings files, an executable file, a hard link, a profile or environment file, and a relative name after a `cd` keep their body visible. `git commit` (it runs hooks), and a passive command with an option that runs a program (`git grep -O`, `rg --pre`, `sort --compress-program`) no longer let a heredoc body be masked; an unknown `uv run` option stops the pytest mask.
- A Grep rooted at an ancestor of the JADE home (for example `~`) is allowed, and MCP file-reader tools are not gated. See docs/05 T19 and backlog W-73.

## [0.2.2] - 2026-11-09

Round H of the review fixes: the permit-approval ancestor check works for the Claude desktop app, SI-09 stops blocking harmless commands, and "never push to the default branch" no longer depends on parsing shell. The false-positive pass that was listed as unreleased after 0.2.1 ships in this release (below).

### Added
- **Standalone pre-push guard (structural SI-08).** `jade git-hook script` prints a self-contained POSIX sh pre-push hook that needs only git and sh at run time. It reads the lines git passes on stdin, resolves the remote's default branch (`refs/remotes/<remote>/HEAD`; `main` and `master` always count too, so a remote whose head points at `trunk` protects all three) and refuses a push whose remote ref is that branch, in every spelling of the refspec (`HEAD:main`, `+main`, `refs/heads/main`, `HEAD:Main`, a delete such as `:main` or `--delete`), with a message that says what to do instead. Tags and branches that only contain the name (`team/main`) pass. It also runs the repository's own `.git/hooks/pre-push` after its check, so installing it through a global `core.hooksPath` does not silently drop that one hook. `jade git-hook check <repo>` reports whether the hook git would run for a repository (it follows `core.hooksPath` from the repository, global or system configuration, and works on a bare repository) is the guard, is executable and is the current version; exit 1 otherwise. **Nothing is installed by jade or by this release**: installing it is a human step (docs/08 section 2.7: per repository in `.git/hooks/pre-push`, or once through a global `core.hooksPath` with its caveat that it replaces other hooks in `.git/hooks` and is overridden by a repository's own hooksPath such as husky's). Branch protection on the remote is the other half and is documented there for GitHub and GitLab. Tests run the script under `sh`, `dash` and `bash` against throwaway repositories and a bare remote (`tests/acceptance/test_git_hook_guard.py`).
- **R-17 (high): what defeats the guard.** `git push --no-verify` (and its abbreviations), `git -c core.hooksPath=...`, `git config core.hooksPath ...` and a write, `chmod`, `rm` or `mv` of `.git/hooks/pre-push` (also through the Write and Edit tools) are rated high with a rationale that names the guard. `git config --get core.hooksPath`, `cat .git/hooks/pre-push` and `jade git-hook script|check` stay low. Decision: a reversible rule change; R-10 and R-15 already rated a push and `git -c` high, so only `git config core.hooksPath` and the hook-file edits are newly gated; the rule sits before R-10 so its rationale is the one shown.
- Work items W-68 (human: install the pre-push guard), W-69 (human: enable branch protection on `vahidkaargar/jade-decision-governance` and the other repositories) and W-70 (SI-10 and the Read and Grep tools); `BACKLOG.md` re-rendered. docs/05 has a new row T23 (push to the default branch).

### Fixed (second pass, verifier findings)
- **SI-09 sees an alias whose quoted value is the whole approving command** (`alias j='jade permit approve'`, `alias j="uv run jade"`) and `env -S "jade permit approve p"` / `env --split-string=...`: the segmenter blanks quoted text, so the invariant now has a `block_quoted` pattern that is also tried on the raw text views. Any alias whose value names `jade` was already blocked when unquoted; this makes the quoted spelling equal. `alias ll='ls -la'`, `env -S 'ls -la'` and an `echo` of the words stay allowed.
- **SI-10 sees a short glob of the key when the command names JADE's state directory** (`cat ~/.local/share/jade/*.key`, `perm*`, `p*`, `*`, so `ls ~/.local/share/jade/*` is now blocked too and `jade ledger stats` is the way to read it; `cd $JADE_HOME && cat p*`): the literal-character threshold applies only to a command that does not name `share/jade`, `JADE_HOME` or the directory it holds, so `rm *.key`, `ls jade/*` and `git add jade/*` are untouched. Recorded residual (W-70): a short glob after a `cd` made in an earlier call.
- **The pre-push guard protects more than main, master and the remote HEAD.** It also protects `init.defaultBranch` and every branch named with `git config --add jade.protectedBranch <name>`, so a default branch such as `trunk` with no `refs/remotes/<remote>/HEAD` can be covered offline. Decision: no `git ls-remote` fallback (a second network round trip and a second credential prompt on every push). `jade git-hook check` now reports per remote whether its default branch is recorded and prints the command that records it (`git remote set-head <remote> --auto`). Decision: the first push of `main` to an empty remote stays refused, because it is a push to the default branch; a human runs `git push --no-verify -u origin main` once (docs/08 section 2.7).
- **R-17 names the environment route** around the guard (`GIT_CONFIG_KEY_n=core.hooksPath`, `GIT_CONFIG_PARAMETERS`); a push through it was already high through R-10, so only the rationale changes.

### Fixed
- **The permit-approval ancestor check recognises the Claude desktop agent (F06 mitigation, docs/05 T2).** The process table was split on spaces, and the desktop app keeps its agent under `~/Library/Application Support/Claude/claude-code/<version>/.../claude`, so no real deployment was ever refused by it. The table is now read as `ps -axo pid=,ppid=,comm=` (the whole executable path) plus `command=` for the arguments, matched by executable name (`claude`, `claude-code`, `claude-agent-sdk`, `codex`, `cursor-agent`, `aider`, `goose`, `opencode`, `gemini`), by bundle path (anything under `Application Support/Claude/claude-code/`, the app's `Contents/Helpers/disclaimer` launcher, the agent SDK and the npm packages of the CLIs) and, for an interpreter, by the script it runs. The Claude app itself and its helpers are deliberately not agents (a human's terminal panel inside the app must still be able to approve). Reading goes through `util.read_process_table`, which tests replace with a synthetic tree (`util.Proc`); **newly refused**: an approval when the process table does not list this process at all (it was allowed). On the maintainer's machine the real chain of this session is found (`claude` under `disclaimer` under the app). Tests: paths with spaces, a symlinked argv[0], truncated Linux `comm`, many agent shapes and human chains.
- **SI-09 is anchored to the approving invocation.** It no longer blocks `ACTION=approve ./deploy.sh` (a variable set to `approve` counts only on its own, `ap=approve; jade permit $ap`), `gh pr review $N --approve` and `kubectl --kubeconfig $KC certificate approve x` (an expansion before the word `approve` counts only as the program or the subcommand), `jade permit approve --help` (usage text), `python -m jade.cli check` and `python jade/cli.py check` (the CLI run as a module or script is the CLI: only its human-only subcommands are SI-09, as for `jade`), or `sed -i 's/permit approve/x/'` (the word pair must start a word). **Newly blocked**, three holes the old pattern had: `jade permit ${X:-approve} prm`, any `jade permit` or `$J permit` whose subcommand is an expansion or command substitution (`jade permit $(echo approve)`), and `export A=approve; $J permit $A prm`. Still blocked and tested: the program path-qualified, behind `env`, `uv run`, `uvx`, `python -m jade`, `python -m jade.cli`, `sudo`, `time`, `nohup`, `script`, `xargs`, in a subshell or group, quoted or split, an alias, function or symlink, and the same code imported from Python. On the replay of 3000 real commands the set of SI-09 blocks did not change. **Behaviour change:** `python -m jade.cli permit list` and `python jade/cli.py check` are no longer SI-09 (the second is still R-16 high).
- **An empty or short `permit-seal.key` fails closed with a clear error** (it raised a raw `TypeError` inside the approval transaction): approving or issuing says the key is N bytes and what a human must do (move it aside; pending permits are then requested again); it is never silently replaced, because every permit sealed with it would then fail. A key that does not exist is still created whole: it is written under a temp name, flushed and linked into place, so no process sees a half-written key. A permit is never verified against a short key.
- **SI-10 sees a glob of the seal key's file name**, not only the literal: `cat ~/.local/share/jade/permit-s*`, `*seal.key`, `permit-seal.k?y`, `permit-[s]eal.key`, `permit-{seal,x}.key`, with quotes in the middle. A glob counts when it would match the file and holds six or more literal characters, one of them a `-` or `.` (eight without), so `rm tmp/*.key`, `ls *seal*` and `**permit**` in prose are untouched; on the replay one command had a markdown `**permit**` and fixed that threshold. Not seen, recorded in W-70: a shorter glob (`permit*`), and the Read and Grep tools, which are not gated at all.

### Changed (false-positive pass, listed as unreleased after 0.2.1)
- Fewer false positives of the command gate, measured on a replay of 3000 real shell commands (`evals/gate_replay.py`, corpus kept outside the repo). Before: 782 high or critical (26.1%), 194 of them (6.5%) outside ssh/scp (R-14), git push (R-10) and composio execute, which stay high by decision. After: 682 (22.7%), and 70 (2.3%) outside those. p99 latency 13 ms before, 6 ms after. No command is high or critical only because of heredoc, prose or inline-data text: the 14 commands that differ when quoted strings are blanked really write a protected file or run a command from inside a program.
  - **Newly allowed (rated low):** text that a non-shell program only prints or stores. The body of a heredoc, a here-string, a pipe into the interpreter, or a `-c`/`-e` argument of python, perl, ruby, node, deno, bun, php, awk, osascript and lua is read by what it does (`jade/interp.py`): literal subprocess, `os.system`, `exec`, backtick and `child_process` arguments are classified as nested shell commands, literal write targets as writes, every other string is ignored. So `python3 - <<EOF` with `print('git push origin main')` is no longer blocked by SI-08; the same program calling `os.system('git push origin main')` still is, and so are programs that write `~/.claude/settings.json` or run `rm -rf /`. A shell interpreter's body (`sh`, `bash`, `zsh`, `dash`) is still scanned whole, and so is a program that starts a shell (every string it feeds is a command). SI-05, SI-09, SI-10 and SI-11 keep reading the raw text.
  - **Newly allowed:** the text of a file written by `cat > f <<EOF` or `printf ... > f` is data; only the destination counts. R-13 (protected config, hooks, ledger, launchers) and R-16 (JADE's own code) are `files_only`: they fire on writes to a protected path or on a command that runs a protected entry point, no longer on a read (`cp ~/.claude/settings.json /tmp/b`, `git add AGENTS.md`, `grep`), on a message, or on a text that names the path. Assignments alone, `mkdir`, and `for`/`case`/`done` lines no longer count as unknown commands; a quoted `|`, `;` or `>` is data (`awk 'NR>1'`); a system-directory program (`/usr/bin/grep`) is the same as the bare name. The checkout of this project is itself called `jade`, so a directory named `jade` that is not the package no longer matches R-16 (`cp x .`, `chmod 644 *.php`, `setup.py`).
  - **Newly blocked:** a directory destination spelled without a trailing slash (`cp x jade`, `install -t jade`, `rsync -a x jade`, `tar -C jade`, `unzip -d jade`, `cd jade && cp x .`) is a write into it; the redirect target of a read-only command (`git show X > jade/hooks.py`, `pytest > f`) and the output options of ruff, pytest, flake8, mypy, pylint and bandit (`--output-file`, `--junitxml`, `-o`) are writes; `>&`, `>|` and `&>` are redirections, not command separators, so `echo x >& ~/.claude/settings.json` is read as the write it is.
  - **Not seen, documented:** a target or command built from input or read at run time, a program run from a script file, and the limits listed in W-67. Classes that need a human decision are W-62 to W-64 and W-66 (branch deletes and `rm -rf` of variables, `ssh -i`, router address list, `.nft` file names, `core.hooksPath=/dev/null`).
  - **Second pass (verifier findings):** the first pass let some literal attacks through, now closed and tested (`tests/acceptance/test_gate_literal_forms.py`, eval cases A134 to A142 and R90 to R95).
    - **Newly blocked again:** a literal command cut into words, `subprocess.run(shlex.split("git push origin main"))`, `"...".split()`, `["git", *"push origin main".split()]`, `os.execvp("git", shlex.split(..))`; a program whose printed output a shell reads, `python3 -c 'print("...")' | sh`, the same with perl, node, ruby, php and awk, in a heredoc piped to a shell, under `eval "$(...)"`, `sh -c "$(...)"`, `bash <(...)` and `xargs -I{} sh -c {}` (every string such a program holds counts as a command; the same program piped to `cat`, `tee` or `grep` stays low); an awk program from stdin (`awk -f - <<EOF`, `-f /dev/stdin`); a command-running function passed as a value (`atexit.register(os.system, "...")`, `functools.partial`, `map`, `Thread(target=os.system, args=...)`, executors, `ctypes` `system()`, `eval(compile("..."))`); a literal command held in a dict, a class attribute, `self.x`, `os.environ`, a list item, or run from a comprehension or a `map(lambda ...)` over a literal list; a relative write after `os.chdir("jade")` or `cwd="jade"`. `xargs -I{} sh -c {}` is read as a shell reading stdin for echo and printf too (it was low).
    - **Newly allowed:** `awk '' in.log > out.nft` (R-01 no longer reads a name after a dot as a firewall command; `nft`, `pfctl`, `iptables`, `ufw` as commands stay critical), `uv init --name jade` (a `--name`, `--project-name`, `--package`, `--app-name`, `--title`, `--namespace`, `--label`, `--hostname` or `--user` value is a name, not a path), and `ssh -i ~/.ssh/id_ed25519 host`, `scp -i`, `sftp -i`, `-o IdentityFile=` (R-04 no longer fires: the key is read to log in and never printed; R-14 still rates the call high, and a key named anywhere else, `scp ~/.ssh/id_rsa host:/tmp`, `ssh-keygen -f`, `cp key`, stays critical). Decision made here, reversible (the mask is `policy._use_identity`); the remaining R-04 cases are W-63. On the replay 13 commands moved down (8 from R-04, 4 from R-01, 1 from R-16) and none moved up.
    - **Still not seen:** base64, hex, `importlib`, a stdin read, a command written to a file and run later, a callback table, `eval` of a built string (W-67).
  - New: `evals/gate_replay.py` classifies a JSON or JSONL file of commands and prints level shares, the share outside the rules a human decided to keep high, the top rules and latency percentiles. It never prints a command; `--save` and `--compare` show what moved between two runs. Tests: `tests/acceptance/test_gate_false_positives.py` (every false-positive class with its true-positive twin, all synthetic), eval cases R80 to R89 and A128 to A133.

## [0.2.1] - 2026-11-09

The first independent adversarial review of 0.2.0 found 48 defects and 18 coverage gaps; this release addresses them in seven clusters; what remains open is documented, not hidden (A1, A2 gate classification and failure behaviour, B permits and the decision lifecycle, C redaction and egress, D judging, adapter and improvement, E installation and health, F tests, docs and backlog). Everything below changes behaviour or documents a limit; items marked **Newly blocked**, **Newly refused** or **Newly failing** turn something that used to pass into a refusal. Permits approved before the upgrade must be requested again (the plan hash, the permit seal and `policy_version` all changed), and the gate matcher is wider: re-run `jade hooks install` in your own terminal and reload the maintain job (`jade launchd-plist`).

### Fixed
- Redaction and docs truth, second pass (review cluster F, verifier findings):
  - **Newly redacted:** a token glued to a word character (`xghp_...`, `123ghp_...`, `_ghp_...`, `xxoxb-...`, `token_eyJ...`, `xsk-ant-api03-...`) is redacted and the second pass knows it, as it did before 0.2.1 for most shapes; the 0.2.1 `\b` anchor had let it through to the provider. Distinctive prefixes (`ghp_`, `github_pat_`, `glpat-`, `AKIA`, `xox*-`, `xapp-`, `AIza`, `whsec_`, `ya29.`, `GOCSPX-`, `eyJ` JWTs) count anywhere; ambiguous ones (`sk-`, `hf_`, `ck_`, `npm_`, `sk_live_`, `pypi-`, `SG.`, `SK` + hex) still need a word boundary unless glued, in which case the match must hold a digit, a capital and a lower-case letter, so `task-...` and `disk-...` slugs are left alone. **Residual:** a glued Twilio `SK` key whose 32 hex characters are all digits (or all letters) is not matched when glued (W-42 covers shapeless secrets).
  - The payload half of the `jade ask` residual check is tested (a token in a question-payload key), and the glued forms are in the redaction corpus and the regression cases.
  - The docs test now also scans the `policies/*.yaml` comments, extracts inline commands inside fenced diagram lines and rejects an unknown flag on a fragment (`jade ask --compat`). Two docs named commands that do not exist (`jade decide classify` in `policies/risk.yaml`, `jade ask --compat` in ADR-03) and are corrected.
- Installation and health (review cluster E: F37-F40, G05):
  - **Newly failing:** `jade check` (and so `jade maintain`) exits non-zero on dead wiring it used to pass: a hook command whose binary is missing or not executable, `disableAllHooks`, an event or matcher that is not the one `hooks install` writes, a registered command that does not decide on a synthetic event (the PreToolUse command must block a `jade permit approve` call with SI-09; probed in a throwaway `JADE_HOME`, gate forced to enforce), gate mode `off`, a `JADE_GATE_MODE` that disagrees with the configured mode, `permissions.defaultMode` bypassPermissions or auto with an advisory or off gate, and a `jade maintain` LaunchAgent that launchd has not loaded.
