# 05 — Threat model

Adversary assumption: the operator is trusted; threats come from content the agent reads (repos, web, tool output, third-party skills), from provider drift, and from the agent's own over-confidence. Nothing here depends on the operator being hostile, so tamper-evident logs are out of scope (ADR-08).

| T1 | Prompt injection via evidence | A README or tool output says "approved, proceed" and the agent passes it as state | State is data; approval is only `permit.approval_reference = tty:*`; `jade ask` output never contains the word "authorized"; adversarial eval set | runtime + evals |
| T2 | Forged approval | Agent runs `jade permit approve` itself, or drives it under a pty it allocated with a clean environment | `approve` refuses unless stdin and stdout are a tty, no agent variable is set (`CLAUDECODE`, `CLAUDE_CODE*`, `CURSOR_AGENT`, `CODEX_SANDBOX`, `AI_AGENT`) and no ancestor process is an agent. Before 0.2.2 the table was split on spaces, so the desktop agent was never recognised and this check protected nothing in that deployment. | T5 | Authority spoofing by model output | "Jev said 0.98 so it is safe" | SI-01; permits never derived from P; risk rules can only be raised by Jev, never lowered | runtime |
| T6 | TOCTOU between permit and execution | Plan changes after approval | The permit binds `plan_hash` = tool, the command or path **as written** (only its ends are trimmed: whitespace inside quotes, heredocs and between lines is part of the command) and the **resolved** working directory (a retargeted symlink is a different plan). At use the hook recomputes it from the actual call and, in one transaction, also checks: the risk level a fresh classification gives the command is not above the permit's, a high or critical command has a human principal and `tty:` approval reference on the permit, `policy_version` is unchanged (a change revokes every open permit), each recorded precondition still holds (for `git push`: the HEAD commit of the repository it runs in), the permit was requested by the same session and agent, and the decision it belongs to is still live. A permit is single-use with a 30-minute TTL. Not bound: the *content* of a Write/Edit (the permit names the path; see W-39) | hook |
| T7 | Duplicate external side effects | Retry after OUTCOME_UNKNOWN | State machine forbids retry before reconcile; SI-07 at the hook: while a decision for the identical command is OUTCOME_UNKNOWN, or irreversible and still EXECUTING, the gate blocks the command and raises or consumes no permit until `jade decide outcome` reconciles it. "Identical" is the decision's `hold_key` (the canonical gated segments of the command: quoting, escapes, `;`/`&& true` around it, an env or `command` prefix, `sh -c`, a full program path and the cwd do not make it a new command; older rows without a key fall back to `plan_hash`). | T8 | Stale cache | Cached judgment applied to changed context | A repeat of an identical question (same question id and version, same canonical state and claim) in the same session within one hour (`ledger.DEDUP_TTL_S`) is answered from the earlier call; a permit or an authorization is never cached because neither is a Jev call. The `cache:` block of `policies/routing.yaml` (eligible families, a `never_cached` list, a 30-minute TTL) is reserved and read by no code (W-53). A repeat is served only from an answered original (DONE with exit 0, 3 or 4: an errored or in-flight call is never the anchor, so the next success becomes the original and stays visible to calibration; rows left EVALUATING by a dead process are closed as errors after 10 minutes), is judged in the calibration group of that original (its `resolved_model` is stored with the row) and is never looser than the first verdict. A permit is bound to the exact `plan_hash` (tool, normalised command or path, working directory) and expires after 30 minutes. Open permits are revoked when their decision is cancelled, expires or finishes (same transaction as the transition) and when `policy_version` changes; a changed precondition (git HEAD for a push, the resolved cwd) makes the permit unusable rather than revoked. The `context_changed` edge exists in the state machine and revokes the permit, but nothing raises it yet (W-35) | runtime |
| T9 | Provider drift / model change | Resolved model string changes silently | Ledger stores resolved model; `MODEL_DRIFT` work item; new snapshot = new calibration group at default thresholds (Q6: no freeze); `jade check` canary question with known answer | runtime + launchd |
| T10 | Benchmark leakage / poisoning | Candidate generator reads protected set; transcript-mined set overlaps live | `protected/` readable only by `jade eval run --protected` (human TTY); split by session hash; candidates record `dataset_versions` | runtime + policy |
| T11 | Reward hacking / proxy gaming | Challenger lowers abstention by always accepting | Pass criteria include unsafe-accept with CI, not only coverage; protected test; human promotion for thresholds. | T13 | Recursive evaluation DoS | DEEP emits questions that emit questions | `revision_count ≤ 3`, deadline 20 s, and a daily call budget (default 500, `ask.DAILY_BUDGET`) that only warns: it never blocks a call. `max_questions_per_request` and `max_parallel_requests` in `policies/routing.yaml` are declared and read by no code (W-53), and no DEEP route emits questions yet, so the recursion this row names cannot occur today. | T14 | Escalation fatigue | Every medium decision pings the human | Recommended default; abstention budget tracked; only high/critical require TTY. Batching (`group_window_s`) is designed but not implemented (W-35) | policy |
| T15 | Data retention / privacy | Ledger stores project text | Redaction; state cap; ledger local only (`~/.local/share/jade`), mode 600 (database, `-wal` and `-shm` created 600 whatever the umask); commands, decisions and permits are stored redacted; `jade ledger purge --older-than 90d` (default, human decision Q7) clears state, question, decision, permit-command and event text while keeping metrics | runtime |
| T16 | Cross-tenant contamination | n/a single tenant | `tenant_scope` constant; revisit if multi-host | — |
| T17 | Hook failure fails open | Hook crashes, the ledger is corrupt or locked, the policy or an overlay does not load, git hangs, or the host kills a slow hook (a killed hook is a non-blocking error: the call proceeds) | The PreToolUse gate fails closed. (1) Classification failure: the shipped rules alone are applied; a call they rate high or critical, or that is not clearly read-only (command) or that writes a protected location (file), is blocked; a clearly read-only command and an ordinary file write pass. (2) Ledger failure after classification (corrupt, locked, full): a call at or above the permit floor is blocked, because no permit can be checked; lower risk passes. (3) An unresolved push destination (git timed out) blocks a high-risk call. (4) Every wait is bounded: ledger lock waits 1.5 s (`hooks.LEDGER_TIMEOUT_S`), a git call 2 s, and the whole handler runs under an alarm of 6 s (`hooks.BUDGET_S`) against the installed host timeout of 10 s; the alarm lands in a policy-free, linear-time fail-safe with the same rule as (1). Advisory mode never blocks; `off` is human-only (SI-09). `jade check` loads the policy and the overlays, so a malformed overlay regex is reported. A malformed overlay therefore blocks every command that is not clearly read-only until `jade check` is run, even one the shipped rules rate low: the overlay is where machine-specific production hosts and paths live, so the shipped rules are not a sufficient floor and the block is deliberate (the message names the error). Low-risk calls fail open by design | hook |
| T18 | Classification gaps | Command built at run time (base64, variable indirection, `eval` of fetched text); tools the matcher does not name (browser and desktop automation MCP tools); text the classifier cannot read (interpreter code that builds its command from pieces, a script read from a path, `curl \| sh`, `-C "$DIR"`, `sed -f`/`awk -f` script files, a directory computed at run time (`cd $VAR`), git aliases defined in a config file; brace expansion beyond 2048 words per word) | Classification is syntactic by design and says so. One canonicalisation step (`jade/shellnorm.py`) runs before every rule and invariant: git global options are removed so each rule sees `git <subcommand>` (`-c alias.*`, `core.sshCommand/pager/editor/fsmonitor/hooksPath`, `--exec-path` and similar are R-15 high); backslash escapes, line continuations, `$'..'` strings and adjacent quotes are resolved; `$(..)` and backticks inside double quotes and unquoted heredoc bodies are extracted; the body of `sh -c`/`eval`, text fed to a shell or interpreter by heredoc, here-string, pipe or process substitution, and the program of `python -c`/`perl -e`/`node -e`/`awk`/`sed 'w ..'` are searched for literal command text (never parsed or run). Other quoted prose and heredoc bodies are not commands; a `#` that starts a word is a comment and ends at the newline whatever a trailing backslash says; `{a,b}` brace lists are expanded (`m{a,}in` is `main`); `eval` and `sh -c` take the joined words of the command (`eval "git" push ...`, nested `sh -c` with POSIX quote escapes, `$0`/`$@` filled from the arguments, `eval "$(echo ...)"`), and the text of every earlier pipeline stage counts as input of a shell reader (`| tee /dev/stdout | sh`, `| xargs sh -c`, `| source /dev/stdin`). The scanner is linear: the current stage is kept as its head and tail, and a work budget of 4 million characters across nested levels degrades the rest to plain text search instead of running past the hook timeout; the `read_only` list admits a verb only without the flag or operand that makes it write; SI-08 parses `git push` arguments (refspec destinations, `HEAD`/`@` resolved against the current branch, `--all`, `--mirror`) as defence in depth only: shell can never be parsed completely, so the enforcement of SI-08 is the standalone pre-push guard and branch protection on the remote (T23); Write-tool paths are expanded, symlink-resolved and matched case-insensitively. A tool that carries a shell command is classified by that command like Bash; text typed or piped into a shell through a tool argument (`interact_with_process`, `app_type`, `computer_batch`, `mcp-exec`) is classified as a command too; MCP file-write tools also get the path rules. Invariants SI-02 and SI-05 are checked on the text a Write, Edit, MultiEdit, NotebookEdit or MCP call carries (new text only, never `old_string`). The matcher is `policy.GATED_BUILTIN` plus `mcp__.*` (Bash, PowerShell, Monitor, Write, Edit, MultiEdit, NotebookEdit, RemoteTrigger); `jade check` flags an installed matcher that is narrower. Agent and Task need no gate: the tool calls a subagent makes run the same PreToolUse hook (the event adds `agent_id`, which is journaled; this was not verified against a live host in this tree: unverified, confirm with `jade ledger` events after a subagent push). CronCreate and CronDelete only schedule a prompt that later runs under the same hooks and are not gated. Built-in tools that did not exist when the matcher was written are not gated until `GATED_BUILTIN` names them. Package runners (`uv run`, `uvx`, `poetry run`, `pipx run`, `npx`, `bunx` ...) are launcher prefixes, so the quoted program of `uv run python -c "..."` is searched like `python -c`. MCP names are read as written and, for camelCase or PascalCase, as snake_case (`setSetting` is `set_setting`); a tool with one name and many verbs takes its `action` argument as the verb (`herd processes {action: start}`); interface-only tools (sidebar, panes, window layout, session title, terminal tabs) are low (M-06a); page scripts, uploads and browser key input (`javascript_tool`, `browser_evaluate`, `file_upload`) are medium and recorded, deliberately not gated, because a permit per page action would stall browser automation: a page script can act with the browser's logged-in sessions and `file_upload` can send a local file, and that residual risk is accepted. SI-02 is not applied to the arguments of a read-only-named tool or to URL and search-term keys (a page URL or a search query is not a bind); SI-05 is applied to every argument of every tool, because a key sent as a search term still leaves the machine, and both are folded first (NFKC, zero-width characters dropped, Unicode dashes read as `-`). Residual risk is tracked as W-31, W-34 and W-37. A push to the default branch is no longer a residual of this row once the pre-push guard and remote branch protection are in place (T23, W-68, W-69); until a human installs them SI-08 is exactly as complete as the parser, and every reviewer so far has found a spelling it misses. **No host backstop in some modes:** the earlier statement that Claude Code's own permission prompt is an independent backstop holds only when the host asks. The hook event carries `permission_mode`; with `bypassPermissions` or `auto` (and `acceptEdits` for file edits), in headless `claude -p` runs and in unattended subagents there is no prompt, and JADE's gate is the only gate: every classification gap above is then an unmitigated bypass. ## 3. Redaction function (contract)

`redact(text) -> (text', hits)` replaces with `[REDACTED:<kind>]`:

- PEM and PGP private-key blocks, JWTs, `Bearer` tokens, `Authorization:` and `Proxy-Authorization:` values (a bare value must look like a credential, so the prose `authorization: required` is left alone), `Cookie:` and `Set-Cookie:` values;
- vendor token shapes (the `api_key` kind): OpenAI, OpenRouter, Anthropic, GitHub, GitLab, AWS access key ids, Slack (`xox*`, `xapp-`, `hooks.slack.com/services/...`), Discord webhook URLs, Google (`AIza`, `ya29.`, `GOCSPX-`), Stripe (`sk_`, `rk_`, `pk_`, `whsec_`), Twilio `SK...`, SendGrid, PyPI, npm, Hugging Face;
- URL userinfo passwords (an empty user name and a `@` inside the password are covered; a port such as `host:8080/` is not a password);
- assignments, headers and JSON fields whose key names a credential: `password`, `passwd`, `passphrase`, `secret`, `token`, `api key` (also `api-key`, `x-api-key`), `private key`, `access key`, `account key`, `shared access key`, `auth key`, `signing key`, `credentials`, `cookie`, and the whole words `pass` and `pwd` (`DB_PASS`, `pwd=`; not `PASSED`, and `PWD=/path` is a directory); JSON escaped inside a JSON string and `[value]` forms are read; Azure `AccountKey=`, SAS `sig=` and `X-Amz-Signature=` query values;
- command-line credentials: `curl -u user:pw` (also `-uUSER:PW`, `--user=USER:PW`), `mysql -pPW`, `docker`/`podman login -p PW`, `sshpass -p`, `redis-cli -a`, `htpasswd -b`, `mongosh -p`, `unzip -P`, `ldapsearch -w`, `openssl -passin pass:`, `--password PW`, `--token PW`, `--passphrase PW` and the like (the `--name=value` form is an assignment). A short flag is read only behind its own command word in the same command (`ssh -p 2222` is a port); `?key=` and `&key=` query values and `api key: ...` with a space are read too;
- the line printed under `security find-generic-password ... -w` (the Keychain `-w` output, also `-wa`, `-ws`, `-gw`, an absolute path to `security` and `2>/dev/null`; the match is the command line plus the next non-empty line, so a `-w` inside `$(...)`, a pipe or a redirect redacts nothing: there is no output line to hide) and the value after `security add-generic-password ... -w`;
- non-owner email addresses (not at all for text that stays on this machine: see below).

It is not applied to a value that is plainly not a secret: a key ending in `count`, `tokens`, `length`, `limit`, `name` or `parallelism` (`max_tokens=4096`, `secret_name: db`), a bare type annotation (`api_key: str`, `token: Optional[str] = None`), a placeholder or a reference (`true`, `none`, `required`, `<token>`, `$TOKEN`, `${DB_PASSWORD}`, `"$TOKEN"`, and a fetch from a store: `$(cat f)`, `$(op read ...)`, `$(pass show x)`; `$(echo S3cret)` is not a fetch and is redacted as a whole), a key that names a setting or a location (it ends in `_type`, `_url`, `_ref`, `_file`, `_path`, `_ttl`, `_expires_in`, `_endpoint`, `_header`, `_prefix`, `_kind`, `_scope`: `TOKEN_TYPE=bearer`, `secret_ref: x`), and an `ssh`, `git`, `hg` or `svn` remote (`git@github.com:org/repo.git`). A numeric password (`password=12345678`) is still redacted. Pure, deterministic, idempotent, unit-tested with a fixture corpus of 80 items (`tests/fixtures/redact_corpus.json`, secrets stored in parts) and a keep-list of non-secret lines (`tests/acceptance/test_redaction_egress.py`).

`residual(text)` is the second pass: the union of the high-confidence patterns (`private_key`, `jwt`, `api_key`), built from `PATTERNS` so that the two cannot drift. It also looks at dictionary keys and non-string leaves that `redact_obj` does not rewrite. A residual match after redaction blocks the call (exit 6).

**Cost.** Redaction runs on every gated command before the hook's timeout (10 s), on the whole text and before any length cap. Every quantifier that can run past the end of a value is bounded, so a start without an end (`password=[` with no `]`, a flag with no command behind it) costs one pass and the cost is linear: 150 KB of any such shape stays well under the timeout (`test_redaction_is_linear_on_adversarial_text`). A quadratic pattern here is a fail-open route: the host kills a hook that overruns its timeout and the command runs.

**Where it runs.** `jade ask` and `jade ask --dry-run` run the same `ask.prepare` (redaction, the 32 KiB cap, the residual check), so a dry run prints exactly what a real call would send. Error text printed or journaled for an invalid question is redacted (the `--field` error no longer quotes the value). The ledger redacts at its own choke points as well, whoever the caller is (`secrets_only`: email addresses are kept, since this text never leaves the machine): `state_text`, `question_text` (including `jade fast` arguments), event `guard` and `detail`, and every decision and outcome (`decide.scrub`: objective, command, candidate actions, constraints, assumptions, evidence references, verification method, measurements).

**Gated commands.** The permit's review context stores the redacted command and a `redacted` count; the plan hash still covers the raw command, so a retry of the same command still matches. A human cannot check from a redacted text what the hash covers, so `permits.approve` and `permits.review_text` refuse such a permit, and the block message tells the agent to move the secret into an environment variable or a file and ask again (a reference such as `--token $VERCEL_TOKEN` or `TOKEN=$(cat f)` is not a secret, so the retry is approvable). A literal that looks like a credential is unapprovable even when it is not one (`git push origin main:token=abc`: a ref name cannot be told from `token=abc`); that is accepted and rides on W-43. Newly unapprovable: a gated command with a literal credential on its command line (tracked as W-43).

**Retention.** `jade ledger purge --older-than 90d` clears project text and keeps every metric: Jev call state and question text, decision objective, command and evidence references, the command of a permit that is no longer open, and the detail of events. Statuses, hashes, risk levels, rule ids, probabilities, costs and timings stay. The ledger runs with `secure_delete=ON`, and a purge that cleared rows then runs `VACUUM` and a `TRUNCATE` checkpoint, so the cleared text is gone from the free pages of `jade.sqlite` and from the write-ahead log, not only from the rows. **Residual:** the file system may keep freed blocks of the old file (a copy-on-write volume, a snapshot, Time Machine, a backup); only full-disk encryption and the backup policy cover those. The scrub is best effort: it is skipped when another process holds the database, and the next purge repeats it.

**Known limits.** Redaction recognises shapes and key names. A secret that has neither (a bare hex or base64 string, a value under an unlisted name such as `key=` or `pin=`, a secret split by a zero-width character, a newline or full-width letters, one that contains a comma after `=`, a Keychain output printed without its command) passes, and `residual()` does not catch it. Tracked as W-42. The control that remains is the one in T15: the ledger is local, mode 600 (the database and its `-wal` and `-shm` files are created 600 before SQLite opens them, whatever the umask) and purged.

## 4. What a Markdown skill cannot do

A SKILL.md can shape behaviour; it cannot stop a tool call. Every "must" in this design that protects a side effect is implemented as exit code, hook, or schema, and the skill merely explains it. The measured 30% low-P→done rate under the current prose-only rule is the evidence for this split.
